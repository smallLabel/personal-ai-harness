# 验证与检查规则

## 类型检查与构建

- 修改代码后**不主动**运行类型检查、构建或 lint 命令。
- 仅当用户明确要求时才执行相关命令。
- IDE 实时诊断信息（diagnostics）可参考并修复明显问题，但不主动触发完整校验。

## 适用命令

- 类型检查（`tsc --noEmit`、`vue-tsc` 等）
- 构建命令（`build` / `build:dev` / `build:pro` 等）
- Lint 命令（`eslint`、`prettier`、`stylelint` 等）
- 启动 dev server 或全量校验的命令

## 例外

- 用户明确说「跑一下 check / 类型检查 / 构建 / lint」等指令时，照办。
- 用户带条件的指令（如「完成后帮我跑一遍 check」），按指令执行。

## 为什么

- 完整校验耗时且打断节奏。
- IDE 已经提供实时反馈，足以覆盖大多数明显问题。
- 用户对何时跑校验有自己的节奏，AI 不应代替决策。
