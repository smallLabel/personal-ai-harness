# UI 风格规则

## 核心原则

UI 设计以**项目现有风格**为准。原型图只作为**布局、字段、流程和功能交互**参考，视觉样式不必照搬。

## 原型图处理方式

- **保留**：页面结构、字段、按钮、弹窗、步骤流程、数据关系。
- **不强制还原**：颜色、字体、阴影、边框、按钮样式、表格样式。
- **冲突处理**：
  - 原型视觉与项目风格冲突 → 以**项目风格**为准。
  - 原型功能与现有组件能力冲突 → 优先**复用现有组件**，通过 props / slots 局部扩展。

## 视觉风格基线

具体视觉规范由项目类型决定，常见后台管理系统约定：

- 整体风格：紧凑、可扫描、重操作效率。**不**做营销化、大卡片化、装饰化。
- 主色 / 语义色：沿用 UI 框架（Element Plus / Ant Design / Naive UI 等）的默认主题色。
- 圆角：小圆角，通常 **4px – 8px**。
- 层级表达：轻量边框、浅背景、弱阴影。**避免**装饰性强阴影。
- 字号 / 行高 / 控件尺寸：遵循 UI 框架默认与项目历史页面。

> 营销页、C 端产品、移动端等场景请按对应风格指南扩展，本规则不强制适用。

## 页面布局约定

- **列表页**：搜索区放在表格上方，主要操作放在表格头部左侧。
- **信息密度**：保持后台系统密度，避免大留白。
- **间距**：优先使用 8 的倍数（**8 / 12 / 16 / 20 / 24 px**）。
- **弹窗**：宽度按内容控制；复杂表单优先**两列布局**。
- **弹窗滚动**：内容超出时**只在弹窗内部滚动**，不允许整页滚动。
- **多步业务流程**：可使用步骤条，视觉保持简洁。

## 项目专属扩展

具体颜色、字号、组件样式细节由各项目自行扩展。建议在项目入口文档（`CLAUDE.md` / `AGENTS.md`）的「UI 规范」区块中维护。
