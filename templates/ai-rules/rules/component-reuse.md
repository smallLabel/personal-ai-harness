# 组件复用规则

## 核心原则

**实现任何新的 UI 功能之前，必须先搜索已有组件，严禁重新实现已存在的功能。**

## 搜索步骤

1. **优先检查同级目录**：当前页面所在目录下是否有 `components/` 子目录（如 `views/<module>/<page>/components/`），有则优先复用。
2. **检查项目共享组件库**：通常在 `src/components/`，按目录浏览并搜索相似命名 / 关键词。
3. **查阅项目文档**：`CLAUDE.md` / `AGENTS.md` 或专门的组件清单文档。
4. **参考同类页面**：找 `views/` 或 `pages/` 下功能相似的页面，看它们用了哪些组件。

## 决策顺序

1. **同级 `components/` 下有匹配组件** → 优先复用。
2. **共享组件库下有完全匹配** → 直接使用。
3. **已有组件接近但不完全满足** → 通过 props / slots 扩展，**不要重写**。
4. **确无已有组件可用** → 创建新组件，放在项目约定的共享位置，并补充到组件清单文档。

## 抽离触发条件

- 同一片段 / 组件在项目中使用 **3 次及以上**时，必须抽离到共享组件库。
- 抽离时同步更新项目入口文档（`CLAUDE.md` / `AGENTS.md`）的组件清单。

## 创建新组件的前置要求

- 跨多页面复用时，新组件应放入共享组件库（项目约定位置，常见为 `src/components/<组件名>/index.vue`）。
- 创建前先与用户确认放置位置和命名。
- 新组件落地后，**必须**在项目文档的组件清单中补充条目（名称、props、暴露方法、典型用法）。

## 常见场景对应

具体「场景 ↔ 组件」对应表在项目入口文档（`CLAUDE.md` / `AGENTS.md`）的「组件清单」区块维护，不在本通用规则里固化。
